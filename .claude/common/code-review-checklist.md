# Code Review Checklist

TDD・AIDD両スキル共通のコードレビュー基準。
code-reviewer、feature-implementer（セルフチェック）が参照する。

> このドキュメントは `.claude/common/` に配置された共通リソースです。

---

## 機能面

- [ ] **要件との整合**: PRD/タスク定義と一致しているか
- [ ] **過剰実装**: 要件にない機能を勝手に追加していないか
- [ ] **不足**: 要件を満たしていない部分がないか
- [ ] **受入基準**: 全ての受入基準を満たしているか

---

## エラーハンドリング

- [ ] **失敗時の挙動**: エラー時にどうなるか明確か
- [ ] **境界条件**: 空、null、最大値、異常値の処理
- [ ] **ネットワークエラー**: タイムアウト、接続失敗の処理
- [ ] **ユーザーフィードバック**: エラー時にユーザーに何を表示するか
- [ ] **回復戦略**: エラーからの復帰方法が定義されているか

---

## パフォーマンス

- [ ] **N+1問題**: ループ内でDBクエリを発行していないか
- [ ] **不要な再計算**: メモ化すべき処理がないか
- [ ] **大量データ**: ページネーション、ストリーミングが必要な箇所
- [ ] **バンドルサイズ**: 不要な依存の追加がないか
- [ ] **レンダリング**: 不必要な再レンダリングがないか（React）

---

## セキュリティ

> 詳細は `.claude/common/security-baseline.md` を参照

- [ ] **入力検証**: ユーザー入力をそのまま使っていないか
- [ ] **権限チェック**: 認可処理が適切か
- [ ] **機密情報**: ログや画面に機密情報を出していないか
- [ ] **SQLインジェクション**: パラメータ化クエリを使用しているか
- [ ] **XSS**: エスケープ処理がされているか
- [ ] **CSRF**: CSRF対策が実装されているか
- [ ] **シークレット**: APIキー等がハードコードされていないか

---

## 可読性・保守性

- [ ] **命名**: 変数名・関数名が意図を表しているか
- [ ] **コメント**: 複雑な処理に説明があるか（不要なコメントは不要）
- [ ] **重複**: DRY原則に従っているか
- [ ] **単一責任**: 関数/クラスが1つのことだけをしているか
- [ ] **複雑度**: ネストが深すぎないか（3段以下を推奨）
- [ ] **型安全**: TypeScript型が適切に定義されているか（該当言語の場合）

---

## テスト品質

> 詳細は `.claude/common/testing-framework.md` を参照

- [ ] **カバレッジ**: 主要なロジックがテストされているか
- [ ] **境界値**: エッジケースのテストがあるか
- [ ] **偽陽性**: 常にパスするテストがないか
- [ ] **偽陰性**: 本来失敗すべきケースがパスしていないか
- [ ] **モック**: モックが過剰でないか
- [ ] **可読性**: テストの意図が明確か

---

## AIが書いたコードの典型的な問題

AIコーディングエージェント特有の問題パターン:

| パターン | 問題 | 対策 |
|---|---|---|
| 過度な抽象化 | 1箇所でしか使わないのにヘルパー/ユーティリティを作成 | 必要になるまで抽象化しない |
| 不要な依存追加 | 標準ライブラリで十分なのに外部パッケージを追加 | 既存依存で解決できないか確認 |
| エラーハンドリング不足 | 正常系のみ実装し異常系を無視 | 全てのエラーパスを確認 |
| テストのモック過多 | 全てをモックして実際の挙動をテストしない | 外部依存のみモック化 |
| 要件外の「改善」 | 指示されていないコードの整形やリファクタ | スコープ内の変更のみ |
| コメント過多 | 自明なコードに冗長なコメントを追加 | ロジックが自明でない箇所のみ |
| 後方互換ハック | 使われていない変数の`_`リネーム等 | 不要なら完全に削除 |

## レビュー判定基準

| 判定 | 条件 |
|---|---|
| **approve** | critical/major issue が 0件 |
| **request_changes** | critical 1件以上、または major 3件以上 |
| **comment** | major 1-2件、またはminor/suggestionのみ |

### Issue severity

| Severity | 説明 | 例 |
|---|---|---|
| critical | セキュリティ脆弱性、データ損失リスク | SQLインジェクション、認証バイパス |
| major | バグ、要件未達、重大なパフォーマンス問題 | N+1クエリ、エラーハンドリング欠如 |
| minor | 可読性の改善、軽微なスタイル問題 | 命名改善、不要なimport |
| suggestion | より良い実装の提案 | 代替アプローチの提示 |
