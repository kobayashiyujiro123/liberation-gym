# Effective Prompt Patterns

AI駆動開発で成果を最大化するためのプロンプトパターン集。
各エージェントおよびユーザーが参照する。

---

## 基本原則

### 具体的な指示が成功率を大幅に向上させる

| 悪い例 | 良い例 |
|---|---|
| foo.py のテストを追加して | foo.py のテストを書いて。ログアウト状態のエッジケースをカバー。モックは使わないで |
| APIが変な理由は？ | ExecutionFactoryのgit履歴を調べて、APIがこうなった経緯をまとめて |
| カレンダーを追加して | 既存のWidgetパターン（HotDogWidget.php）に従って、月選択と前後ページネーション付きのカレンダーウィジェットを実装して |

### 効果的なプロンプトの構造
1. **目的**を明確に
2. **参照すべきファイル/パターン**を指定
3. **制約条件**を明示
4. **期待する出力形式**を指定

## Phase別プロンプトパターン

### Phase 1: Explore（探索・要件定義）

#### インタビュー開始
```
以下のアイデアについて、要件定義を行いたいです。

アイデア: [簡単な説明]

私にインタビューしてください。以下の観点で質問を1つずつ行い、
私の回答を踏まえて次の質問をしてください：

1. ターゲットユーザーと課題
2. 競合・代替手段との差別化
3. 必須機能とNice-to-have
4. 成功の定義（KPI）
5. 技術的制約・予算・期限
6. エッジケースとリスク

**重要**: 当たり前の質問はせず、以下を引き出す質問をしてください：
- 隠れた前提
- 未検討のエッジケース
- 必要なトレードオフ
```

#### フロー可視化
```
以下の要件に基づいて、主要なユーザーフローをMermaid図で作成してください：

[要件をここに貼り付け]

作成するフロー：
1. 新規登録フロー（正常系 + エラー系）
2. メイン機能のフロー
3. 課金フロー（該当する場合）
```

#### 状態遷移図
```
以下の要件に基づいて、主要なエンティティの状態遷移図を
Mermaid stateDiagram-v2 で作成してください：

[要件をここに貼り付け]

各状態について以下を明記：
- 状態名
- その状態に遷移するトリガー
- 異常系の遷移（タイムアウト、キャンセル等）
```

### Phase 2: Design（デザイン）

#### デザインシステム定義
```
以下のプロダクトのデザインシステムを定義してください：

プロダクト: [名前]
ターゲット: [ユーザー層]
雰囲気: [形容詞で3-5個]

以下を定義：
1. カラーパレット（Primary, Secondary, Accent, Background, Text）
2. タイポグラフィ
3. スペーシング
4. 基本コンポーネント（ボタン、カード、入力フィールド）

Tailwind CSSの設定ファイル形式で出力してください。
```

#### UIプロトタイプ
```
以下のワイヤーフレームを元に、Reactコンポーネントを作成してください。

[ワイヤーフレームを貼り付け]

要件:
- Tailwind CSSでスタイリング
- モバイルファースト
- ダミーデータで動作確認できるように
- インタラクティブに
```

### Phase 3: Review（批判的レビュー）

```
以下の要件定義について、厳しい批判的レビューを行ってください：

[要件定義を貼り付け]

### 市場・ビジネス面
- このサービスが失敗する最も可能性の高い理由は？
- ターゲットユーザーは本当にこの課題を持っているか？

### 機能・設計面
- 抜け落ちている重要な機能は？
- 矛盾している要件は？

### 技術・実現性面
- 技術的に困難な部分は？
- セキュリティリスクは？

問題点を指摘した後、改善案も提示してください。
```

### Phase 4: Plan（スプリント計画）

```
以下のPRDに基づいて、実装スケジュールを作成してください。

[PRDを貼り付け]

条件：
- 1スプリント = 3-5日
- 各スプリントは独立してテスト可能な単位
- 依存関係を考慮した順序
- 各タスクの見積もり時間を記載

出力形式：
1. スプリント一覧（目標と成果物）
2. 各スプリントのタスク分解
3. 依存関係図（Mermaid Gantt）
4. リスクがあるスプリントの特定
```

### Phase 5: Code（実装）

#### スプリント開始
```
Sprint {N}を開始します。
docs/plans/sprint-{N}-implementation.md を参照して、
タスク{N}.1から順に実装してください。

各タスク完了時に：
1. 何を実装したか簡潔に報告
2. テスト結果を表示
3. 次のタスクに進んでよいか確認
```

#### コードの探索（実装前）
```
src/{directory}/ を読んで、{機能}の仕組みを理解して。
まだコードは書かないで。
```

#### 計画立案
```
{機能}を追加したい。
どのファイルを変更する必要がある？
計画を立てて。think hard
```

#### 実装指示
```
{画面名}を作成して。

参照: src/components/{Pattern}.tsx のパターンに従う
機能:
- {機能1}
- {機能2}
制約:
- モバイルファースト
- 既存のTailwindクラスのみ使用
- 新しいnpm依存は追加しない

まずこの1画面だけ作成。think
```

### Phase 6: Commit

```
変更をコミットして、PRを作成して。

PR本文に以下を含めて：
- docs/PRD.md への参照
- docs/plans/sprint-plan.md#sprint-{N} への参照
- テスト結果のサマリー
```

## 状況別プロンプトパターン

### バグ修正
```
以下のエラーが出ました：
{エラーメッセージ}

{何をしようとしていたか}

試したこと：
- {試したこと1}
- {試したこと2}
```

### コードレビュー依頼
```
src/{file} をレビューして。
セキュリティ、パフォーマンス、可読性の観点で。
```

### リファクタリング
```
src/{file} のリファクタリングを提案して。
現在の機能は変えずに、可読性と保守性を改善したい。
まず計画を提示して、承認後に実装。think hard
```

### コードベース学習
```
「ロギングはどう実装されてる？」
「新しいAPIエンドポイントを追加するには？」
「{file}の{line}行目は何をしてる？」
```

## プロンプト改善チェックリスト

- [ ] 目的が1文で説明されているか
- [ ] 参照すべきファイル/パターンが指定されているか
- [ ] 制約条件が明示されているか
- [ ] 「まだコードは書かないで」等の行動制限があるか（必要な場合）
- [ ] 「think」「think hard」等の思考深度指定があるか（複雑な場合）
- [ ] 期待する出力形式が指定されているか
- [ ] 曖昧な表現がないか
